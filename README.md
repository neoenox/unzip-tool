# かんたん解凍 (unzip-tool)

Windows向けのシンプルな解凍ソフト。zip/tarは依存なし、rarのみ外部ツールが必要。

## 対応形式

- `.zip` (パスワード対応)
- `.7z` (パスワード対応)
- `.rar` (RAR4/5、パスワード対応、要UnRAR)
- `.tar` / `.tar.gz` / `.tgz` / `.tar.bz2` / `.tbz` / `.tar.xz` / `.txz`

※ 分割アーカイブ / 自己解凍形式は非対象（non-goal）。詳細は「仕様メモ」の非対象（non-goal）と変更の基準を参照。

## RARに必要なもの

いずれか1つ。無ければrar選択時に案内が出る。

1. WinRARをインストール (UnRAR.exe を自動検出)
2. `tools/UnRAR.exe` を置く（exeと同じ場所、またはリポジトリ直下。同梱しない）
3. 環境変数 `KANTAN_UNRAR` にUnRAR.exeのパスを指定

`KANTAN_UNRAR` を指定したときはそのパスだけを使う（見つからなければ他候補へは
落とさず、指定パス付きの案内を出す）。

UnRARはフリーウェア ([rarlab](https://www.rarlab.com/rar_add.htm) のUnRAR for Windows)。
管理方針は (a) バイナリはgit管理外＋各自/CI調達（`tools/UnRAR.exe` はコミットしない）。
入手手順と検出順は [tools/README.md](tools/README.md)、ライセンス全文は
[tools/license.txt](tools/license.txt)。本リポジトリはUnRARのバイナリを配布しない。

## 開発環境の構築

Python 3.11 を推奨（CI の exe ビルドと同じ版）。リポジトリ直下で次を実行する。

```bat
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt -r requirements-build.txt
```

RAR の実展開テストには UnRAR が必要。[tools/README.md](tools/README.md) の手順で `tools/UnRAR.exe` を配置する（バイナリはgit管理外）。テストの実行方法は後述の「テスト」を参照。

## 使い方

```bat
run.bat
REM または
python app.py
```

1. 書庫をウィンドウのドロップ領域へドロップ、または領域をクリックして「ファイルを選ぶ」で追加する。複数選択できる。
2. 保存先を確認し、「解凍する」（複数の場合は「まとめて解凍する」）を押す。全体バーに ○/○件が出る。完了時は音とタスクバー点滅で通知する。
3. パスワードが必要な書庫は、そのカード内のパスワード欄に入力する（Enterでも実行できる）。カードのどこをクリックしてもその書庫が選択される。
4. 完了したカードの「フォルダを開く」で結果を確認する。失敗・中断したカードは「再試行」でその書庫だけやり直せる。不要なカードは「×」で外せる。空き容量不足は「保存先を変更して再試行」、パスワード待ちは「パスワードを入力」ボタンが出ます。

- 各カードの「内容を見る」でその書庫のフォルダ構造を表示する。
- 保存先は初期状態で書庫と同じ場所の `アーカイブ名/`。同名のファイル・フォルダがあれば `アーカイブ名 (2)/` のように連番になる。既存ファイルを上書きしない。
- 保存先の「変更」やフォルダのドロップは、全未完了書庫の保存先の親フォルダを変更する（カードで個別変更した書庫は上書きしない）。保存先欄を直接編集した場合は選択中の書庫だけ変更し、個別扱いになる。各カードの保存先欄の「変更」でその書庫だけ変えられる（「（個別）」と表示）。
- 一覧取得と解凍はバックグラウンドで実行する。解凍中は「キャンセル」で処理中と残りの書庫を停止できる。完了済みの結果は残る。
- 完了・失敗は各カードに表示する。パスワード待ちや失敗した書庫があっても、残りの書庫を処理する。

## ショートカット

| キー | 動作 |
| --- | --- |
| `Enter` | 解凍する（解凍中は無効） |
| `Delete` | 選択中の書庫を一覧から外す（ファイル自体は削除しない） |
| `Ctrl+O` | 書庫を追加 |
| `↑` / `↓` | 書庫の選択を移動（選択したカードへフォーカスし、必要なら一覧をスクロール） |
| `F1` | ヘルプを開く |
| `Esc` | ヘルプを閉じる |

パスワード欄・保存先欄・「内容を見る」のツリーにフォーカスがある間は、入力操作を優先し、これらのショートカットは働かない（`Enter` はそのボタン本来の動作になる）。`Tab` でヘッダーや各カードの操作へ移動できる。

## 設定とヘルプ

- ヘッダーの「ヘルプ」、または `F1` で、対応形式・できないこと・保存先の決まり・ショートカットをアプリ内で確認できる。モーダルではないので開いたまま操作を続けられる。
- 前回の保存先とウィンドウ位置は `%APPDATA%\KantanKaiko\settings.json` に記録し、次回起動時に復元する。保存先のフォルダが消えている場合や、ウィンドウが画面外に戻ってしまう位置は無視して既定値から始める。

## exe化

ローカル `build.bat` と GitHub Actions は同じPyInstaller引数でビルドします。`KantanKaiko.spec` は自動生成・Git管理対象外であり、製品のビルドには使いません。UnRARは方針(a)（バイナリはgit管理外・各自/CI調達）によりexeに同梱しません。
詳細は [tools/README.md](tools/README.md)。

```bat
build.bat
REM → dist\KantanKaiko.exe ができる (単一ファイル、Python不要)
REM UnRARは同梱しない。RARはWinRAR/外付けUnRAR/KANTAN_UNRAR経由で利用
```

## インストーラー

`KantanKaiko-Setup-1.2.10.exe` を実行すると、日本語の案内でユーザー専用フォルダ（標準は `%LOCALAPPDATA%\Programs\KantanKaiko`）にインストールする。管理者権限は不要。スタートメニューに登録し、デスクトップのショートカットは任意で作成できる。Windowsの「インストールされているアプリ」からアンインストールできる。

インストール時のタスクで「アーカイブをダブルクリックしたときの既定アプリにする」を選ぶと、`.zip` / `.7z` / `.rar` / `.tar` / `.tgz` / `.tbz` / `.txz` / `.gz` / `.bz2` / `.xz` の既定アプリに登録します（既定はオフ。`.gz` 等は汎用形式なので注意）。Windows 11 の UserChoice 保護で効かない拡張子があるため、その場合は Windows の設定 → アプリ → 既定のアプリから拡張子ごとに「かんたん解凍」を選んでください。

ローカルで作成する場合はInno Setup 6を用意し、先に `build.bat` でexeを作成する。

```powershell
./scripts/build-installer.ps1 -Version 1.2.10
# → dist/KantanKaiko-Setup-1.2.10.exe
```

`-Version` を省略すると `version.py` の値をそのまま使う。版数はこの1ファイルだけが持ち、PRのCIもリリースworkflowもここから読む。両者は `windows-build.yml` を共通で呼び、テスト・ビルド・検証の手順を共有する。

PRのCIではインストール・ショートカット・バージョン登録・再インストール・アンインストールと、追加したユーザーファイルを消さないことまで検証する。リリースタグのpushでは、通常のexeとタグのバージョン番号を付けたインストーラーの両方をReleaseへ添付する。

リリースタグ（`v1.2.10` など `v*`）をGitHubへ作成・pushすると、GitHub Actionsがそのタグのコードをテスト・ビルドし、同じタグのReleaseへ `KantanKaiko.exe` とインストーラーを自動添付する。ローカルでタグを作っただけでは実行されない。

タグの公開前に、対象コミットがmainに含まれることとタグの版数が `version.py` と一致することを確認する。テスト・ビルド失敗時やexeが未生成・空の場合は公開処理へ進まない。通常のブランチpush・PR・手動実行ではReleaseを作成しない。新しい変更をリリースする場合は、対象のPRをマージしたコミットへタグを付ける。

```bat
git tag v1.2.10
git push origin v1.2.10
```

## テスト

```bat
python tests/run_all.py
```

pytest は `run_all.py` からは実行されない pytest 専用回帰（更新確認キャンセルの終了処理など）も拾う。完全チェックには次も実行する。

```bat
python -m pytest --tb=short -q
```

安全性、キャンセル、異常終了、7z、RARと、実物のAppウィンドウで複数書庫・パスワード再試行・GUI解凍・同一プロセス内DnD・別プロセス通知の堅牢性を検証する。RARの実展開テストはUnRAR未検出時にスキップする。
Windows CIは exe をビルドする 3.11 に加えて、3.13 でも同じテストを実行する（exeの同梱Pythonは3.11のまま）。
真のExplorerドロップ配送や「プログラムから開く」はOLE共有メモリとシェル登録に依存するため自動化できない。人が確認する手順は [docs/manual-explorer-qa.md](docs/manual-explorer-qa.md) にまとめてある。

公開したリリースそのもの（資産のサイズとハッシュ、実exeの起動時の設定復元、画面外座標の拒否、更新確認）は `scripts/verify-release.ps1` で確認する。ウィンドウを表示するためCIでは動かさない。

```powershell
pwsh -File scripts/verify-release.ps1
```

## 仕様メモ

- DnDはpoll方式: WndProc内ではTkを一切触らない (別プロセス通知時の再入で落ちるため)
- 日本語zipの文字化け対策あり (cp437 → cp932 再デコード)
- 全形式で展開前に危険パス、Windows特殊名、名前の衝突を検査する。リンクや特殊ファイルを含む書庫はエラーとして拒否する。
- 保存先と同じ親の一時フォルダで展開し、成功した結果だけ専用フォルダへ移す。失敗・キャンセル・通常終了時は一時ファイルを片付ける。
- ZIP / TAR / RARの展開中は処理済み容量・割合・経過時間を表示する。7zは不定進捗と経過時間を表示する。
- ZIPの暗号対応は標準ライブラリのZipCrypto。AES暗号ZIPは非対象。
- 非対象（non-goal）と変更の基準: 分割アーカイブ、自己解凍形式、AES暗号ZIP、既存保存先へのマージは対象外（「あとで追加する」予定ではない）。見直す場合は、①一般ユーザーの誤操作・混乱リスクが増えない、②既存の安全検査とテストを壊さない、③README・ヘルプ・QA手順を同時に更新できる、の3条件をすべて満たすこと。
- アプリの強制終了や電源断では `.kantan-*` 一時フォルダが残ることがある。既存の解凍結果は変更しない。
- UIの配置は `ui.py`、状態と順次処理は `app.py`、作業プロセスは `jobs.py`、解凍と検査は `unzipper.py`、保存設定は `settings.py`。
- 更新確認・ダウンロードは子プロセスで行う。子プロセスを作れない環境では同じ API のスレッド版ワーカーへ退避し、更新確認を継続する。
- 設定は `%APPDATA%\KantanKaiko\settings.json` の1ファイルにまとめる。テストは環境変数 `KANTAN_SETTINGS_DIR` でこの場所を実ユーザーの設定から切り離し、`UNZIPTOOL_NO_UPDATE_CHECK=1` で起動時の自動通信を止める。

修正計画は [docs/implementation-plan.md](docs/implementation-plan.md)。PRではWindows CIが全テストとexeビルドを実行する。

### 更新の確認

起動時に1日1回（前回チェックから24時間以上経過したときだけ）公式リリースを確認する。新しい版があれば、公式アセットのインストーラーをダウンロードして GitHub が公表する SHA256 で検証し、`/VERYSILENT` で適用した後にアプリを終了する。手動でも画面上部の「更新を確認」から同じ処理を実行できる。適用した版は次回起動時に「vX.Y.Z に自動更新しました」と12秒間表示される。ダウンロードや適用に失敗した場合は案内を表示して起動を続ける。アプリのバージョンは `version.py` で管理し、リリースタグはその値と一致させる（現在は `v1.2.10`）。PRのCIもこの値からインストーラー名を決めるため、リリース時の変更は `version.py` の1行だけ。

Windows CIではビルドしたexe自身の作業プロセスで、UnRARがない場合の案内と、UnRARがある場合のRAR3/5展開を検証する。UnRARはexeに同梱しない。`KANTAN_UNRAR` を指定したときはそのパスだけを使うため、手元（WinRAR導入機）でも同じ手順で確認できる。

```powershell
python tests/test_frozen_rar.py --exe dist/KantanKaiko.exe --unrar tools/UnRAR.exe
```
