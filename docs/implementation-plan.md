# 解凍処理とUIの改善計画

対象: [Issue #1](https://github.com/neoenox/unzip-tool/issues/1)

## 方針

Python / tkinterと既存の対応形式を維持する。初期画面はドロップ領域を中心にし、追加した書庫をカードで表示する。通常操作は「追加 → 解凍 → フォルダを開く」。書庫ごとに専用フォルダへ保存する。既存の保存先へマージする機能は用意せず、同名の保存先があれば連番にする。

元の作業場所の未コミット変更は取り込まず、origin/mainから独立した作業場所で実装する。

## 1. 安全な解凍

- `unzipper.py`: 展開前に全エントリを検査。絶対パス、親ディレクトリ参照、Windows特殊名、リンク・特殊ファイル、大文字小文字を無視した名前衝突、ファイルとフォルダの衝突を拒否する。
- 保存先と同じ親に作った一時フォルダで展開。全ファイルの読み込みに成功してからrenameで結果を公開する。読み込みはストリームで行う。
- 失敗時は読み取り専用ファイルも含め一時フォルダを清掃する。既存の結果は変更しない。
- 検証: ZIP/TAR/7zの展開、CRC異常、危険名、リンク、既存保存先、途中の例外、読み取り専用ファイルの回帰テスト。

## 2. バックグラウンド処理

- `jobs.py`: 一覧取得と解凍を別プロセスで実行する。子プロセスは一時フォルダへ書き込み、親が結果を受け取って初めて保存先へ公開する。
- キャンセル時は所有するプロセスツリーを停止して一時フォルダを清掃する。子の異常終了も検出する。
- GUI側は書庫オブジェクトとパスワードの世代番号で結果を対応付け、古い結果が別の選択や新しい入力を上書きしないようにする。
- 7zは中間の件数進捗を保証できないため、不定進捗を表示する。
- 検証: 非同期一覧、親の受理前には結果が公開されないこと、実行中・完了直後のキャンセル、異常終了。

## 3. 操作画面

- `ui.py`: 明るい背景、青い主要ボタン、余白のあるドロップ領域と書庫カード。
- `app.py`: 複数書庫を順番に解凍し、成功・失敗・パスワード待ちを個別表示する。
- 内容一覧は折りたたみ式のフォルダツリー。先頭2000エントリまで表示し、総数・容量は全エントリから計算する。
- パスワードは必要なときだけ表示。表示切り替え、再入力、Enterで再試行できる。成功後はメモリ上の入力を消す。
- 完了・失敗は画面内で通知。成功した書庫に「フォルダを開く」を表示する。
- 保存先の「変更」は全未完了書庫の親フォルダを変更。入力欄の直接編集は選択中の書庫のみ変更する。
- 解凍中は書庫追加・保存先・パスワードの変更を停止し、選択・内容確認・キャンセルは可能にする。
- 検証: 実物のTkウィンドウで初期表示、複数書庫、内容ツリー、パスワード再試行、キャンセルと再試行、選択変更、既存DnDを確認する。

## 4. 検証とPR

- `tests/run_all.py`で各テストを実行し、失敗時は即座に停止する。
- PR用Windows CIでテストとexeビルドを実行する。タグのリリース処理も同じテスト入口を使う。
- 実ウィンドウの表示、exeの起動・バックグラウンド処理を確認する。
- READMEに操作、保存先、キャンセル、形式別の制限を記載する。
- PRにIssue、変更点、検証結果、未検証項目を記載する。マージ・リリースは今回の範囲に含まない。
